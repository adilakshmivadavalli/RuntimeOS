# RuntimeOS — local development in VS Code

Extract the ZIP and open the `RuntimeOS` folder in VS Code. The archive includes
the React application, FastAPI backend, Python and TypeScript SDKs, tests,
benchmarks, documentation, and GitHub workflows.

## Prerequisites

- Python 3.11, Node.js 20 or 22, and Yarn Classic (1.22).
- A running local MongoDB server, or your own MongoDB connection string.
- Internet access to install dependencies. VS Code does not install runtimes.

## 1. Configure your local environment

Copy `backend/.env.example` to `backend/.env`, and
`frontend/.env.example` to `frontend/.env` using VS Code's file explorer.

In `backend/.env`, set `MONGO_URL` and `DB_NAME` for your own database, set
`ADMIN_EMAIL`, `ADMIN_PASSWORD`, and `ADMIN_ORG_NAME`, and replace `JWT_SECRET`
with a fresh value generated by:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Use a strong local admin password even though there's no login screen to type
it into — the product opens straight into the console, transparently
authenticated as this seeded admin (see the "No login screen" note below).
`ADMIN_PASSWORD` still matters because it's usable directly against the
`/api/auth/login` endpoint (still functional, just not called by the UI) and
because changing these variables does not reset an account already in your
database.

Keep `ENVIRONMENT=development` and `ALLOWED_ORIGINS=http://localhost:3000` for
local HTTP browser sessions. The frontend's `REACT_APP_BACKEND_URL` should be
`http://localhost:8001`. Use `localhost` consistently in the browser.

Keep `.env` files private and out of version control. Existing hosted credentials
and database contents are deliberately not included in this archive.

## 2. Start the backend (VS Code terminal 1)

```bash
cd backend
python -m venv .venv
```

Activate the virtual environment:

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Windows Command Prompt:

```bat
.venv\Scripts\activate.bat
```

macOS / Linux:

```bash
source .venv/bin/activate
```

Then, in the same terminal:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m uvicorn server:app --reload --host 127.0.0.1 --port 8001
```

The dependency file installs cleanly with a standard `pip install -r requirements.txt` —
payments use the official `dodopayments` SDK directly. Set `DODO_PAYMENTS_API_KEY` and `DODO_PAYMENTS_WEBHOOK_KEY` in `backend/.env` if you
want to exercise the `/api/payments/*` routes locally; every other route works without them.

## 3. Start the frontend (VS Code terminal 2)

From the extracted project root:

```bash
cd frontend
yarn install
yarn start
```

Open **http://localhost:3000**. Backend API documentation is at
**http://localhost:8001/api/docs**. Keep MongoDB and both terminals running.

**No login screen.** The console opens straight to the dashboard, authenticated
as the admin seeded from your `.env` above — there's nothing to sign in with.
`POST /api/auth/login` still works if you want a real token for scripting or
testing against a specific user, but the UI never asks for one.

## SDKs

- Python: see `sdks/python/README.md`; install from the project root with
  `python -m pip install -e ./sdks/python`.
- TypeScript: see `sdks/typescript/README.md`; inside that folder run
  `yarn install` followed by `yarn verify`.
- SDK API keys must be created in your own local console; hosted keys are not
  copied into this archive.

## Included and excluded

This is a source-code export, not a database backup or a bundled runtime.
Installed dependencies, generated builds, caches, Git history, internal session
files, private credentials, and prior test reports are excluded. Local `.env`
templates are included. Known configured secret values are redacted from the
exported source copies without changing the running application's source.

Dodo Payments checkout needs a separately configured `DODO_PAYMENTS_API_KEY` locally; it is
not functional with the empty template value. Enterprise connectors retain
their existing **MOCKED / partially implemented** behavior; the export does
not add connector implementations.

### Memory provider

Breeth provides persistent, intent-aware agent memory via its REST API. RuntimeOS keeps tenant governance, policy decisions and audit records in MongoDB while Breeth stores/searches agent memory.
